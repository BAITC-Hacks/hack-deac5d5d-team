# Эксперименты и воспроизведение аудита

Ниже сохранены измерения от **23 сентября 2026 года**:
CPython 3.14.0, macOS arm64; 2 248 клиентов, 3 119 направленных рёбер,
4 840 операций и 19 изолятов. Исторические JSON в `experiments/results/`
содержат параметры, версии и хеши на момент измерений. Их пути и хеши исходников
относятся к той версии кода, до переноса модулей в пакет.

Команды повторения выполняются из корня проекта. Новые отчёты записываются
в игнорируемую папку `reports/`, отдельно от сохранённых протоколов.

## Полный пайплайн

Пять запусков каждого варианта в отдельных процессах, без профилировщика.
Каждый запуск читает и проверяет Parquet, выполняет расчёт и публикует
проверенный комплект в новую временную папку.

| Вариант | Анализ, медиана с | Публикация, медиана с | Пайплайн, медиана [min–max], с | Весь процесс, медиана [min–max], с |
|---|---:|---:|---:|---:|
| До исправлений | 1.317 | 0.118 | 1.497 [1.462–1.594] | 1.893 [1.857–2.349] |
| Новый, diagnostics off | 1.170 | 0.620 | 1.856 [1.850–1.895] | 2.277 [2.247–2.311] |
| Новый, diagnostics on | 1.363 | 0.632 | 2.060 [2.050–2.078] | 2.468 [2.449–2.498] |

«Пайплайн» начинается после основных импортов; «весь процесс» включает запуск
Python, импорты и завершение. Измерялся API полного расчёта без форматирования
консольной сводки. Медианы этапов рассчитаны независимо и не обязаны складываться
в медиану всего пайплайна. Варианты чередовались с циклическим сдвигом; отдельного
прогрева и сброса файлового кэша не было. Установка зависимостей и удаление
временных файлов не измерялись.

Отключение старого временного признака экономит **0,204 с, около 9,9%**
от времени режима с диагностикой. SHA-256 основных ролей, оценок, кластеров,
приоритета и объяснений совпали во всех запусках двух новых режимов.
Точное посредничество сохранено по всем 2 248 источникам.

Весь исправленный пайплайн без диагностики медленнее прежнего на **0,359 с,
около 24%**: добавлены денежные контракты, BFS, разделение кластеров, расширенный
JSON, проверка комплекта и хеширование. Сравнение целых версий не выделяет
эффект одной оптимизации и не предполагает равенства их результатов.

[Полные времена, порядок запусков, версии и SHA-256](../experiments/results/benchmark-results.json).
Исходные данные и код проверены по хешам до и после серии; изменений не было.
Это локальные измерения, не гарантия скорости на другой машине или холодном диске.

Повторение двух текущих режимов:

```bash
.venv/bin/python experiments/benchmark_pipeline.py --project . --runs 5
```

Для сравнения с отдельным старым checkout добавьте `--baseline /path/to/old/project`.
Базой может быть прежний корень или его плоская папка `starter/`; текущая версия
берётся из корня с `hackalem/`. Параметры `--data`, `--report`,
`--output-json` переопределяют пути. Входные Parquet, исходники и существующий
результат не изменяются.

## Louvain и Leiden

Сравнены 18 вариантов: два алгоритма, seed **7, 42, 99** и resolution
**0,5; 1; 1,5**. В обоих случаях встречные потоки складываются в одной
неориентированной проекции, самопереводы исключены, изоляты выделены отдельно.
Louvain дополнен обязательным разделением групп по компонентам связности.
Leiden использует `RBConfigurationVertexPartition` и `n_iterations=-1`
до отсутствия улучшения. Версии: NetworkX 3.7, igraph 1.0.0, leidenalg 0.11.0,
pandas 3.0.6.

При seed=42, resolution=1:

| Показатель | Louvain + компоненты | Leiden |
|---|---:|---:|
| Кластеров | 89 | 97 |
| Несвязных итоговых групп | 0 | 0 |
| Modularity | 0.858876 | 0.861975 |
| Coordinator | 42 | 39 |
| Изменилось ролей относительно Louvain | 0 | 3 |
| Средний Jaccard между seed при resolution=1 | 0.8565 | 0.8970 |

Jaccard сравнивает множества пар клиентов в одном сообществе; номера кластеров
не сравниваются. Modularity сопоставима только при одной resolution.
Внешний оборот — доля сумм направленных рёбер между сообществами; меньшая доля
сама по себе не означает лучшую предметную кластеризацию.

Все 18 итоговых разбиений связны и покрывают клиентов ровно один раз.
Для каждой комбинации заново рассчитаны зависимые признаки и роли.
**Состав и порядок топ-20 совпали во всех вариантах**, хотя отображаемые
роли его участников иногда менялись.

При resolution=1 Leiden показал более высокую modularity во всех трёх seed
и большую среднюю устойчивость между seed. При resolution=0,5 устойчивость Leiden
оказалась ниже. Это не обосновывает автоматическую замену алгоритма:
основной вариант остаётся Louvain с разделением компонент.

Измерялся один запуск каждой комбинации после прогрева: проекция, преобразование
в igraph и разделение компонент, без загрузки Parquet и дальнейшего анализа.
Это сравнение конкретных Python/C++ реализаций. Единичные короткие замеры
не дают надёжного вывода об ускорении, а три seed на одном графе — о правильности ролей.

## Повторение сравнения и аудита

Leiden — необязательная зависимость эксперимента; основной запуск её не требует.
Для отдельного окружения:

```bash
python3.14 -m venv .venv-experiments
.venv-experiments/bin/python -m pip install -r requirements.txt igraph==1.0.0 leidenalg==0.11.0
.venv-experiments/bin/python experiments/compare_communities.py --data data --out reports/community-experiment.md --with-roles
```

Без `--with-roles` сравнивается только кластеризация.
Обоснование алгоритма:
[Traag, Waltman, van Eck: From Louvain to Leiden](https://arxiv.org/abs/1810.08473);
параметры реализации:
[документация leidenalg](https://leidenalg.readthedocs.io/en/stable/reference.html).

[Повторное воспроизведение аудита](../experiments/results/audit-after.json)
зафиксировало исправление денежной границы 35%, ошибочной глубины, пересечения
путей, несогласованного JSON, гонки чтения при миграции, влияния самопереводов
на приоритет и несвязных сообществ. Все проверки успешны; исходные Parquet
не изменились.

```bash
.venv/bin/python experiments/audit_acceptance.py --data data --output reports/audit-after.json
```

Алгоритмы, пороги и ограничения — в [методике](methodology.md);
тесты и статус проверки платформ — в [руководстве по разработке](development.md).
