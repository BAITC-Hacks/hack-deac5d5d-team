# Граф денег — интерфейс и топ клиентов

В ветке `interface` реализованы топ **50 клиентов**, поиск по `gid` среди всей сети,
направленный граф связей, фильтры ролей/кластеров и карточка с числовыми объяснениями.

Из корня репозитория в Python-окружении проекта:

```bash
python run.py
```

Откройте **`out/index.html`** двойным щелчком. Команда также формирует и проверяет
`nodes_roles.csv`, `clusters.csv`, `top_nodes.csv` и `graph.json` в папке `out/`.
Готовая аналитика команды подключается через `python run.py --analysis path/to/results`.
Без этого параметра работают документированные базовые правила на реальных данных.

Установка, интерфейс, формулы, ограничения, тесты и демо: **[interface/README.md](interface/README.md)**.
Исходный `starter/starter.py` по-прежнему создаёт учебные шаблоны; для заполненного
топа и интерфейса запускайте корневой `run.py`.

## HTML-прототип Lense

Готовый самостоятельный интерфейс: **[interface/lense-demo.html](interface/lense-demo.html)**.
Скачайте файл и откройте его в браузере двойным щелчком — установка зависимостей и сервер не нужны.

Прототип включает интерактивный граф на четыре колена, поиск и выбор узлов,
фильтры периода и суммы, временную шкалу, карточку с основаниями проверки,
очередь проверки, просмотр операций, экспорт CSV и текстового отчёта.
Используется название **Lense**, без значка и названия Freedom Bank.

В этом файле все данные вымышленные: 128 счетов, 846 переводов, общий объём 74,2 млн ₸.
Он предназначен для демонстрации интерфейса и не подключён к данным `data/*.parquet`;
аналитическое приложение на данных репозитория по-прежнему запускается через `python run.py`.
Отметки «Добавить в проверку» хранятся только до перезагрузки страницы.

# Датасет: 4-хоповый граф внутрибанковских переводов (июль 2026)

## Что это

Граф внутрибанковских переводов от 81 клиента, только по исходящим переводам.

## Параметры сбора

| Параметр | Значение |
|---|---|
| Seed | 81 gid |
| Период | 2026-07-01 — 2026-07-31 |
| Глубина обхода | 4 колена |
| Направление | только исходящие |
| Порог по сумме | ≥ 5 000 KZT |

## Итоговые цифры

| Колено | Новых узлов |
|---|---|
| 0 (seed) | 81 |
| 1 | 472 |
| 2 | 462 |
| 3 | 789 |
| 4 | 444 |
| **Итого** | **2248 узлов** |

Плюс: **3119** рёбер (уникальных пар плательщик→получатель), **4840** отдельных транзакций.

## Файлы

### `data/edges.parquet`
Одна строка — одна пара (плательщик → получатель), агрегированная за весь период.

| Колонка | Тип | Смысл |
|---|---|---|
| `src` | int64 | gid плательщика |
| `dst` | int64 | gid получателя |
| `sum_kzt` | float64 | сумма всех переводов между этой парой за июль 2026 |
| `n_tx` | int64 | количество отдельных транзакций, вошедших в сумму |
| `depth` | int8 | на каком колене обхода это ребро было найдено (1-4) |

### `data/nodes.parquet`
Одна строка — один уникальный gid, встретившийся в графе (включая seed).

| Колонка | Тип | Смысл |
|---|---|---|
| `gid` | int64 | идентификатор клиента |
| `depth` | int | минимальное колено, на котором клиент впервые появился (0 = seed) |
| `is_seed` | bool | `True`, если это один из исходных 81 |

### `data/transactions.parquet`
Не агрегировано — одна строка на каждую отдельную транзакцию по уже найденным рёбрам.

| Колонка | Тип | Смысл |
|---|---|---|
| `src` | int64 | gid плательщика |
| `dst` | int64 | gid получателя |
| `date` | date | дата транзакции |
| `sum_kzt` | float64 | сумма конкретной транзакции |
